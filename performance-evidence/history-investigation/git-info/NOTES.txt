The custom update_root.rs harness retains #3146's Criterion sample size (10), flat sampling, warmup (1 s), measurement target (5 s), reset outside the clock, and output assertions. Its one history_100_root fixture places the package at the Git root instead of packages/package-0. The manifest disables README inference and excludes benchmark configuration/scaffolding from packaging so initial package snapshots still equal the release. An extra assertion rejects the initial `add README` commit from the generated changelog.

Reason for the root fixture: in #3146's nested workspace fixture, Cargo lists a generated Cargo.lock next to the package manifest, but only the workspace root Cargo.lock physically exists. Package-file canonicalization therefore falls back to conservative commit inclusion, bypassing git show entirely. The root variant exercises the normal changed-file intersection path and the batched Git subprocess optimization.

Build the harness using the original benchmark-harness.patch, then copy update_root.rs to crates/release_plz/benches/ and append a [[bench]] section named update_root with harness = false to crates/release_plz/Cargo.toml. Use the same compiled harness against saved baseline and optimized release-plz executables with run-history-benchmarks.py. No benchmark changes belong in the production PR.
